# Parity corpus (issue 23)

The pinned level/seed/input corpus for the parity harness. Consumed by the
`crates/oh-parity` test crate (`cargo test -p oh-parity`, part of the
`cargo test --workspace` gate); regenerated/verified by `bash tools/parity.sh`.

Evidence classes (see `.agents/plans/001-rust-port/PARITY.md` for the results
table and the documented gaps):

| File | Evidence class | Regenerated by |
|---|---|---|
| `rng_streams.json` | **C++-probe-derived** — the REAL `src/SSVOpenHexagon/Core/RandomNumberGenerator.cpp` (the `advance(1)` wrapper shift + libstdc++ uniform distributions), bit-exact f32/f64 + int streams for 7 seeds | `tools/oracle/parity_probe.cpp` (via `tools/parity.sh`) |
| `replay_serialization.json` | **C++-probe-derived** — the REAL `src/SSVOpenHexagon/Core/Replay.cpp`: byte-exact file / zlib-level-9 / `sf::Packet` forms of the mixed-keyboard-stream fixture + the four alwaysSpinRight SEEDED-REPLAY envelopes (seed 987654321, F×0x02 where F is the pinned death frame, the pinned score) + the `replay_player` cursor walk | `tools/oracle/parity_probe.cpp` (via `tools/parity.sh`) |
| `pack_ids.json` | **C++-probe-derived** — the REAL `Utils/BuildPackId.cpp` + `Utils/LevelValidator.cpp` for all 8 shipped `_RELEASE` packs (the base pack ships no levels: its validator pin uses the documented synthetic `<packId>_nolevels` id, format coverage only) | `tools/oracle/parity_probe.cpp` (via `tools/parity.sh`) |
| `level_runs.json` | **Rust-self-consistent (analytically anchored)** — the SEEDED REPLAY run per level pair (pinned death frame + input count + score, deterministic in the pinned seed + stream; verified stable across independent processes) and the live `alwaysSpinRight` run's pinned PROPERTIES (all-0x02 recorded bytes; the recorded replay reproduces the live score exactly — the live OUTCOME is seed-dependent by C++ design, see its `evidence` field); C++-source-derived anchors cited per entry (timekeeping identity, the 5 per-frame RNG advances, input-byte semantics). The full C++ game build is unavailable on this machine (no SFML/LuaJIT/ImGui dev environment) — the gap is documented in PARITY.md | the `oh-parity` tests pin the values on every `cargo test` run |

Reproducibility rule (plan-process): every C++-derived byte above is
regenerable from the committed script + committed C++ sources
(`bash tools/parity.sh` builds and runs `tools/oracle/parity_probe.cpp` and
byte-compares its output to this directory — a mismatch means the ground
truth drifted or the corpus was hand-edited). The mixed-keyboard-stream
fixture additionally cross-checks the pre-existing
`mapping/oracle-vectors.md` pins (replay fixture 1).

Level pairs: the six `_RELEASE` pack/level entries the determinism harness
(`crates/oh-game/tests/determinism.rs`) exercises — the 2-pair 25-iteration
`ReplayExecution` loop + the 4-pair 100-iteration `ReplayExecutionBenchmark`
loop — reduce to the four unique pairs in `level_runs.json` (cube/apeirogon
and experimental/autotest0 appear in both loops).
