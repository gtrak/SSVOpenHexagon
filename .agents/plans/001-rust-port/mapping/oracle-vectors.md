A pure-Python reimplementation of the above matched every value, confirming the
algorithm is fully characterized:

```python
M = 6364136223846793005; MASK64 = (1<<64)-1
def out(internal):
    rshift = (internal >> 61) & 7
    internal ^= internal >> 22
    return (internal >> (22 + rshift)) & 0xFFFFFFFF
class PCG:
    def __init__(self, seed): self.state = (seed | 3) & MASK64
    def next(self):
        old = self.state; self.state = (self.state * M) & MASK64; return out(old)
```

in UTC; numbers formatted via `ssvu::concat` (default ostream float formatting).

Behavior: `std::ostream <<` for `float`/`double` uses `%g`-like default precision
(6 significant digits), drops trailing zeros and the decimal point when integral.
An `f32 1.6` prints `1.6` (not `1.60000002`); `3600.0` prints `3600`.
`buildPackId` replaces space/newline/tab with `_` in each of
disambiguator/author/name then joins with `_` and appends the int version.
`getLevelValidator(levelId, diffMult)` = `concat(levelId, "_m_", diffMult)`.

## SFML `Packet` encoding rules (verified from the fork source)

Read from the pinned fork `vittorioromeo/SFML@dacceddbd1adee49c7bfd120266e200800550394`,
`src/SFML/Network/Packet.cpp`:

| type | bytes |
|---|---|
| `bool` | 1 (0/1) |
| `int8`/`uint8` | 1 raw |
| `int16`/`uint16` | 2 **big-endian** (`htons`) |
| `int32`/`uint32` | 4 **big-endian** (`htonl`) |
| `int64`/`uint64` | 8 **big-endian** (manual byte shifts) |
| `float`/`double` | raw `memcpy` — **host-endian** (LE on x86), NOT byte-swapped |
| `std::string` / `const char*` | u32 **big-endian** length, then raw bytes |
| `append(data, n)` | raw bytes |

**This is a trap:** the replay *file* format uses `std::memcpy` directly (host-endian
little-endian), while the replay *packet* form goes through `sf::Packet`, which
big-endian-encodes the u64 length prefix. So `HEX` starts `05000000` (LE u32) but
`PHEX` starts `0000000000000054` (BE u64 = 84). The Rust port must use
`to_le_bytes` for the file format and `to_be_bytes` for the packet format.

Corrected `PHEX` (the packet form) is shown in the block above.

## RNG wrapper (`hg::random_number_generator`) — what the game actually uses

**This section supersedes the plain-engine distributions above for game behavior.**
`random_number_generator::random_number_generator(seed)` constructs `pcg32_fast{seed}`
and then calls `advance(1)` (from `src/SSVOpenHexagon/Core/RandomNumberGenerator.cpp`).
Because the engine is `output_previous == true`, that makes the first value drawn
through the wrapper equal to the **fresh engine's second** output. The plain-engine
`int=`/`real=` blocks above are the *unshifted* stream and are NOT what the game
observes.
