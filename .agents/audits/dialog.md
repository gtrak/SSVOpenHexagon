# Audit: Dialog pair — C++ `HexagonDialogBox` vs Rust `oh-menu::dialog_box` (+ its drivers in `MenuGame` / `menu_draw`)

Scope: 1:1 port audit of ONE module pair.
- C++: `src/SSVOpenHexagon/Core/HexagonDialogBox.cpp` (309 lines, read completely) + `include/SSVOpenHexagon/Core/HexagonDialogBox.hpp`.
  Because `HexagonDialogBox` itself owns **no** event handlers, the audit focus items (dialog state machine, input gating
  `setIgnoreAllInputs`, draw) are driven from `src/SSVOpenHexagon/Core/MenuGame.cpp` — the dialog's only consumer — which was
  read in full for the dialog-relevant paths (ctor onEvent blocks `:259-726`, `changeStateTo` `:830-907`, online menu items
  `:1596-1655`, `okAction`/`eraseAction` dialog call sites, `update` `:2511-2874`, `setIndex` colors `:2998-3000`,
  `setIgnoreAllInputs` `:3390-3402`, `reloadAssets` `:3092-3127`, `draw` dialog pass `:5968-5972`, dialog show-helpers
  `:6107-6161`).
- Rust: `crates/oh-menu/src/dialog_box.rs` (read completely) + its driver surface: `crates/oh-menu/src/menu_game.rs`
  (`show_dialog_box` / `show_input_dialog_box` / `handle_net_event` / `change_state_to` / `handle_text_entered` /
  `handle_release_edge` / `update` / `set_index`), `crates/oh-menu/src/menu.rs` (online items), `crates/oh-menu/src/states.rs`,
  `crates/oh-app/src/menu_draw.rs` (`draw_dialog_box`, the C++ `drawText` pass), `crates/oh-app/src/windowed.rs`
  (`refresh_input` drain, font-oracle wiring).

Method: (1) C++ behavior inventory; (2) Rust implemented list; (3) adversarial diff. Every absence was verified by a recorded
grep ("absence proof" column). Risk per item: uservisible-gameplay | uservisible-cosmetic | determinism | data-format |
internal | none.

Summary: **4 MISSING** (3 uservisible-gameplay, 1 uservisible-cosmetic), **8 SEAMS**, **9 DIFFERENT**.

## VERDICT

**FAIL 1:1.** The `HexagonDialogBox` data model, frame-quad math, and `drawText` pass are ported (with cosmetic geometry drift — D1–D6), but the dialog **state machine is unwired in Rust**: typed characters never reach the input box (C++ `MenuGame.cpp:491-517` has no counterpart), and Enter/Escape releases neither advance the registration/login/delete-account sequence nor cancel it — `tryRegister`/`tryLogin`/`tryDeleteAccount` are unreachable and the whole online dialog flow (C++ `MenuGame.cpp:384-489`) is dead. Single most important gap: **the missing dialog-input state machine (MISSING #1–#3) — the online login/registration flow cannot be completed or entered in the Rust port.**
