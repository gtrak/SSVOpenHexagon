# SSVOpenHexagon — a literal 1:1 Rust port of Open Hexagon

This repository is a **file-by-file Rust port of [SSVOpenHexagon](https://github.com/SuperV1234/SSVOpenHexagon)**
(Open Hexagon) — the ~42k-line C++20 game by Vittorio Romeo. The port mirrors the
original's structure rather than redesigning it: same modules, same function
order, same constants, `float`→`f32` and `double`→`f64` verbatim. The goal is a
Rust binary that is behaviourally indistinguishable from the C++ one — replay
determinism included — so that replays, save data and level packs are
interchangeable between the two.

The C++ original lives in this repo, unmodified, under **`cpp-original/`**
(moved there by the 038 reorganisation; see
[`.agents/plans/001-rust-port/DECISIONS.md`](.agents/plans/001-rust-port/DECISIONS.md),
D-038). It is the **reference this port is verified against**, and the citation
corpus — code comments that cite the C++ as `file:line` — addresses it through
the root symlinks `src/` and `include/` (→ `cpp-original/src`,
`cpp-original/include`), so pre-reorg citations keep resolving. The game data
shared by both implementations (assets, packs, configs, the Steam/Discord
native stubs) lives in `_RELEASE/` at the root.

## How it was built (the method)

This is not a rewrite; it is a port with evidence. The pieces that make "1:1"
a claim rather than an aspiration:

- **Frame-level parity against the instrumented C++.** The C++ reference is
  built in a reproducible container (`tools/cpp-oracle/`) with a minimal,
  off-by-default `-fingerprint` hook applied from
  [`tools/cpp-oracle/fingerprint.patch`](tools/cpp-oracle/fingerprint.patch).
  The hook emits a per-frame hash of game state (RNG, walls, player, score,
  custom score, status timers, entities) plus the draw count. The port runs the
  same replayed inputs and must match the C++ column frame for frame:
  **3627 frames across 6 corpus cases** are committed in
  [`.agents/plans/001-rust-port/parity/cpp_fingerprints.json`](.agents/plans/001-rust-port/parity/cpp_fingerprints.json)
  and re-checked on every gate run, alongside byte-exact C++-derived corpora
  (RNG streams, replay serialization, pack ids) regenerated by compiling the
  *real* C++ sources against minimal shims (`tools/parity.sh`). A 43-case Lua
  A/B corpus pins the scripting layer too.
- **The gate.** Every change passes `bash tools/gate.sh`: `cargo fmt` check,
  workspace build, `clippy -D warnings`, the full test suite, and a Lua-parity
  stage that runs N separate VM processes against the committed vectors.
- **The deviations register.** Every deliberate divergence from the C++ is
  documented with a reason in
  [`.agents/plans/001-rust-port/deviations.md`](.agents/plans/001-rust-port/deviations.md)
  (F1…F30). If you find a behaviour difference that is not there, that is a bug
  to report, not an accepted one.
- **Citation discipline.** Rust sources cite the C++ original as
  `file:line` (the D-014 rule: a citation that does not resolve is a defect).
  That corpus is why the C++ tree is archived in-repo and why the root
  `src`/`include` symlinks exist.

## Features

What the game itself is (inherited from the C++ original, all present in the
port):

- A fast arcade level-advancement game: survive, upgrade the score multiplier,
  don't crash — with the 180° swap mechanic, curving and accelerating walls,
  and per-pack story levels.
- **Level packs** shipped in `_RELEASE/Packs/` (the tracked set includes the
  classic cube/babysteps packs), plus user levels: **custom levels and custom
  walls are Lua scripts** — the same `CustomTimeline`/wall-script model as the
  C++ original.
- **Replays**: byte-exact `.ohr.z` compression, in-game replay watching, and a
  workshop-uploader tool (`oh-workshop-uploader`) that publishes replays as
  Steam Workshop items.
- **Online**: a C++-compatible score server (`oh-server-control` / the C++
  `HexagonServer` protocol), client leaderboards with local caching, and
  encrypted (libsodium) wire messages — on-disk and wire compatibility with
  the C++ server is pinned by tests.
- **Steam integration**: achievements, workshop UGC upload (the default build
  links no SDK, exactly like the C++'s no-SDK build; `--with-steam` opts in).
- **Discord** rich presence (local-client IPC, mirroring the C++ behaviour).
- A **Lua console** in the game (the `u_*` API surface, engine-shimmed and
  deterministic) — the same scripting API the C++ exposes.
- Config overrides, profile persistence, and joystick support, matching the
  C++'s `config.json` format (a 101-key file, pinned byte-for-key).

**One Lua VM.** Since the Luau unification (D-037) the port ships a single VM —
Luau, across every platform — with a compatibility prelude for the
Lua-5.1-isms the game uses. The LuaJIT machinery was deleted; the C++ column
remains the ground truth either way (the fingerprint compares game state, not
VM internals).

### Platforms

| Platform | Status |
|---|---|
| Linux | Primary target. Full gate green; packaged by `tools/package.sh` (smoke-tested headless replay included). |
| Windows | Cross-built from Linux (GNU triplet, `tools/build-windows.sh` / `tools/package.sh --windows`). |
| Android | **Real-device verified** (issues 31/34: touch overlay, boot-to-playback); packaged by `tools/package-android.sh`. |
| wasm / web | Builds (emscripten, whole app) and runs in a browser — boot, engine loop and input verified via the emsdk container; the hosted page (GitHub Pages) is in-flight release work (issue 37), so treat it as "working build", not a shipped product. |

## Building and testing

- `bash tools/gate.sh` — fmt / build / clippy `-D warnings` / tests / Lua parity (the bar every commit must meet).
- `bash tools/package.sh` — Linux release package into `target/package/` (a
  `_RELEASE`-shaped directory you can drop the binary into, C++-style).
  `--windows` for the cross build.
- `bash tools/package-android.sh` — the Android APK.
- The C++ reference column: `tools/cpp-oracle/run.sh` (container build of the
  original; `tools/cpp-oracle/fingerprint.patch` is the only instrumentation,
  off by default and reversible).

## Repository layout

- `crates/` — the port (oh-app, oh-game, oh-render, oh-lua, oh-parity, …).
- `cpp-original/` — the untouched C++ original (citation reference + oracle
  source). Root `src`/`include` are symlinks into it.
- `_RELEASE/` — the shared game data (assets, packs, configs, native stubs);
  read by both the port and the C++ build.
- `tools/` — the gate, packagers, the oracle harnesses, lane tooling.
- `.agents/` — plans, decisions (DECISIONS.md), audits, skills and task
  reports — the project's engineering record.
